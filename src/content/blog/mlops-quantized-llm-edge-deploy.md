## The Self-Hosted AI Infrastructure Shift

Relying solely on external cloud LLM APIs introduces API latency spikes, usage costs, and privacy vulnerabilities when processing sensitive enterprise data. Quantized open-weights models (like Llama 3 8B, Qwen 2.5, or Mistral 7B) running locally via GGUF 4-bit quantization deliver 95% of full-precision accuracy on consumer GPU or CPU hardware.

In this guide, we'll build a self-hosted local inference API service using **FastAPI**, **vLLM PagedAttention**, and **Server-Sent Events (SSE)** streaming.

```
User App Request
       │
       ▼
┌───────────────────────────┐
│ FastAPI Gateway           │
│ (Input Validation & Auth) │
└─────────────┬─────────────┘
              │ Streaming SSE
┌─────────────▼─────────────┐
│ vLLM Inference Engine     │
│ - PagedAttention Memory   │
│ - Quantized GGUF Weights  │
└───────────────────────────┘
```

## Dockerized vLLM Server Setup with CUDA Acceleration

vLLM utilizes **PagedAttention** to eliminate VRAM fragmentation, achieving 2x-4x higher token generation throughput compared to standard HuggingFace transformers.

Here is the Docker Compose configuration for launching local quantized inference:

```yaml
version: "3.8"

services:
  llm-engine:
    image: vllm/vllm-openai:v0.4.2
    environment:
      - HUGGING_FACE_HUB_TOKEN=${HF_TOKEN}
    ports:
      - "8000:8000"
    volumes:
      - ~/.cache/huggingface:/root/.cache/huggingface
    ipc: host
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
    command: >
      --model Qwen/Qwen2.5-7B-Instruct-GGUF
      --quantization gguf
      --max-model-len 4096
      --gpu-memory-utilization 0.85
```

## FastAPI Server-Sent Events (SSE) Streaming Wrapper

To stream generated tokens back to client frontend interfaces as they are generated by the model:

```python
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
import httpx
import json

app = FastAPI(title="Local Quantized LLM Gateway")

VLLM_ENDPOINT = "http://localhost:8000/v1/chat/completions"

@app.post("/api/v1/generate")
async def generate_completion(prompt: str):
    headers = {"Content-Type": "application/json"}
    payload = {
        "model": "Qwen/Qwen2.5-7B-Instruct-GGUF",
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.7,
        "stream": True
    }

    async function token_stream():
        async with httpx.AsyncClient(timeout=60.0) as client:
            async with client.stream("POST", VLLM_ENDPOINT, json=payload, headers=headers) as response:
                if response.status_code != 200:
                    raise HTTPException(status_code=500, detail="LLM engine error")

                async for line in response.aiter_lines():
                    if line.startswith("data: "):
                        data_str = line[6:].strip()
                        if data_str == "[DONE]":
                            break
                        try:
                            chunk = json.loads(data_str)
                            delta = chunk["choices"][0]["delta"].get("content", "")
                            if delta:
                                yield f"data: {delta}\n\n"
                        except json.JSONDecodeError:
                            continue

    return StreamingResponse(token_stream(), media_type="text/event-stream")
```

## MLOps Deployment Checklist

1. **VRAM Memory Budgeting**: Always cap `--gpu-memory-utilization` (e.g. `0.85`) to reserve memory for KV cache expansion during long context conversations.
2. **Context Window Selection**: Match context window sizes (`--max-model-len`) precisely to application requirements to avoid unnecessary VRAM overhead.
